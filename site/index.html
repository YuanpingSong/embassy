Embassy

A local embassy for your AI agents. Embassy is a small local broker that lets a Claude Code session and a Codex CLI task on the same Mac message each other by name, with a receipt for every delivery — and the receipt never claims more than it proved. delivered means the provider boundary was crossed: toward Claude, the native mailbox write (transport_written) completed; toward Codex, the App Server accepted the turn. held is progress, never success, and unconfirmed or ambiguous means the evidence is missing. Claude-bound mail is written immediately; Codex-bound mail waits for an idle turn. The recipient answers with the conv_ token it was delivered, and no state ever implies a model read the message. Local, single-user, unofficial — not affiliated with or endorsed by Anthropic or OpenAI.

Quickstart

Each command is what the shipped CLI accepts once you substitute your host. Replace your-host with the hostId on the broker's ready line.

# install, and run the broker as your launchd agent
npm install -g agent-embassy
embassy service install
# 1. inside the Codex task — ask the agent to run it
embassy register-codex --alias codex-reviewer@your-host
# 2. read the live Claude session names
embassy status
# 3. from the Codex task — body via stdin, never an argument
embassy send --from codex-reviewer@your-host --to advisor@your-host --expects-reply <<'MSG'
Which auth middleware did you settle on?
MSG
# 4. the recipient answers with the token from its reply hint
embassy send --conversation conv_<token> --from advisor@your-host <<'MSG'
The session-scoped one; the risk is the double-write window.
MSG

Everything else — the shell-peer fallback, federation, embassy check after an upstream update, and safety in one minute — is in the README. What each release changed is in the changelog.

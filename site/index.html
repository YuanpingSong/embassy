Why

Three moments this exists for

If you run more than one agent, you already know them.

Mid-flow

Your agent has a question

Claude hits a decision Codex already made. Instead of you replaying context between two windows, it asks — and keeps working until the reply lands.

Away from desk

The reply routes without you

Codex-bound questions wait honestly for an idle turn boundary. Answers back to Claude enter its mailbox immediately, even while Claude is busy. Nothing needs you watching a terminal.

Small footprint

Almost nothing to install

Claude needs no Embassy commands at all — its native ListAgents and SendMessage discover and message the peers Embassy advertises to it. A Codex task runs one CLI command to register. DeepSeek and Grok Build are declared in config and started by the broker when a message needs them.

Providers

Four flags, one gate

Claude Code and Codex keep their native transports, because those deliver into the live session you already have open. DeepSeek and Grok Build arrive over ACP — the open Agent Client Protocol — as sessions Embassy launches and owns. Every one of them routes through the same broker, the same consent edges, and the same ledger.

Claude Code

Native peer protocol over a private Unix-domain socket. Mail lands in the live session you are working in: discovery, selection, and a mailbox write with a correlated native receipt. peerProtocol 1 is exact wire grammar, checked per record.

Codex

The managed App Server over a local subprocess Embassy owns. A registered task is resumed and observed; a message enters at an idle turn or at a validated tool-call boundary — never mid-generation.

DeepSeek

An ACP session launched from your local dsh harness checkout (DSH_HOME, default ~/.dsh) — the published adapter is not spawnable. No checkout, no pretending: the route renders degraded with its exact safe code. Its receipts are deliberately coarse; see the protocol section.

Grok Build

An ACP session from the registry's exact pinned artifact — npx --yes @xai-official/grok@1.0.5 agent stdio. There is no adapter to package. Capabilities are read from this connection's initialize response and honored as read, never assumed in advance.

The cost of the next flag: the ACP client is 562 lines and the shared provider adapter is 212. DeepSeek and Grok Build together landed in under 800 changed lines — a launch spec and an honest receipt mapping each, not a new transport. The honest limit that comes with it: ACP v1 is spawn-only, so an ACP provider talks to Embassy through a session Embassy owns, not through a TUI you have open in another window.

How it works

Six commands to a working route

Each command is exactly what the shipped CLI accepts.

embassy serve

Start the broker. It opens no network listener — everything stays on this machine. Configured ACP providers register their routes at boot (dsh-main@this-mac and grok-main@this-mac by default); their subprocesses start lazily, on the first message that needs one.

embassy register-codex --alias codex-embassy@this-mac

Run inside the Codex task — identity is inherited from the task, never impersonated. Ask your agent to run it.

embassy select-claude --alias claude-main@this-mac

Select the Claude route. Selection creates no consent edge.

embassy pair --from codex-embassy@this-mac --to claude-main@this-mac

Create the explicit bidirectional consent edge used by the next send. Both endpoints must be registered, live, on the same host, and on different providers.

embassy send --from codex-embassy@this-mac --to claude-main@this-mac <<'MSG'

The envelope crosses — body via stdin, never an argument. You get a dlv_ receipt and a conv_ token back.

Protocol truth

The register doesn't flatter you

Every claim below means exactly what it says — that's the product.

delivered ≠ read

Toward Codex, delivered means App Server accepted the turn. Toward Claude, it means the native mailbox write completed. Toward an ACP provider, it means that provider's session answered the prompt. None of them implies the body was read, understood, or acted on.

direction determines timing

Codex-bound messages wait for idle or the exact STEER next-tool boundary; a Codex wait may show as held — progress, not success — and Embassy never interrupts mid-generation. Claude-bound messages enter Claude's mailbox immediately, busy or idle. An ACP-bound message is prompted on dispatch, and the agent's answer comes back on the same conversation.

tested with, not certified

A release says what it was tested with — provider, transport, exact artifact, protocol, and the honest limitations of each lane — in one release-owned support matrix. It is a claim about our testing, not a runtime permission system: a test proves the matrix file is never imported by the running broker.

runtime claims only what it proved

There are no evidence tiers, no compatibility probes, and no version gate anywhere at runtime. Authority to route is consent plus the exact owned route identity; success is what this connection, this route, and this correlated operation demonstrated. Version numbers are unverified metadata, and no version fact grants or withholds anything.

an unconfirmed receipt is the honest one

The DeepSeek adapter collapses aborted, blocked, and error outcomes into end_turn, so an end_turn from that lane proves nothing. Embassy settles it unconfirmed with ACP_OUTCOME_COARSE rather than call it delivered. A genuine cancellation still settles cancelled. The collapse is upstream and unrecoverable from the client side; the receipt stays honest until the adapter does.

restarts stop dropping mail

Queued mail survives a broker restart and re-sends exactly once when its route returns. In-flight-at-crash settles ambiguous — never silently lost, never double-sent.

consent is per edge, and every message says who sent it

A routed message needs an exact consent edge between its two endpoints — role-neutral records bound to both endpoints' leases — and paired inbound is the default; embassy serve --inbound open is the one deliberate way to relax it. Every routed body arrives inside one broker-composed provenance envelope naming the sender, the originating provider, and the reply token: attribution the sender cannot forge.

the OS boundary is the perimeter

embassy serve binds nothing. Identity is attested at the operating-system boundary — same machine, same user, exact executables, private mode-0600 sockets and state — and never asserted by a name. Embassy binds no TCP port and serves no HTTP.

bounded by design

An accepted message is capped at 16 KiB; an ACP reply is capped at 64 KiB and marked truncated rather than trimmed in silence; queues, conversations, retention, and deadlines are all bounded; a dead agent subprocess backs off on a fixed ladder instead of spinning. Embassy answers every ACP permission request with a refusal — never an approval.

a routed message is a new input path

Treat anything that arrives as untrusted input to its receiver — the same discipline you'd apply to any tool result.

delivered

The direction's provider boundary was crossed: App Server accepted a Codex-bound turn, Claude's native mailbox accepted a Claude-bound write, or an ACP session answered the prompt. None means read.

unconfirmed

Embassy could not confirm the direction's delivery boundary — including the case where the provider's own adapter destroys the evidence. Not a failure; not a success. It stays unconfirmed rather than guessing.

ambiguous

Conflicting signals about settlement, or a subprocess that died with the outcome outstanding. Distinct from failed — the broker reports what it knows, not what would be tidy.

expired

The message deadline elapsed before settlement. Terminal, and visible in the ledger with the deadline that killed it.

The vocabulary

Words that mean things

Registration & consent edges

The permission model. A Codex task registers itself; a Claude session is paired to it; ACP routes are declared and boot-registered. An edge is the deliberate act that lets two of them talk, and only the paired may talk — unless you deliberately open inbound.

The ledger

Receipts for every delivery, with states that never overclaim. The register of record when you ask "where is my message?"

The pouch

Transit. Sealed en route: the broker moves messages, it does not read them.

Consulates

Four flags fly today. Because new providers arrive over an open standard, the next one is a launch spec and a receipt mapping — same embassy, same consent rules, one more flag.

For agents

Teach your agent the protocol

The embassy-peer skill teaches an agent how to address peers, interpret receipts, and reply with the conversation token. Install it, then invoke with $embassy-peer.

# Claude Code
cp -R "$(npm root -g)/agent-embassy/skills/embassy-peer" ~/.claude/skills/
# Codex
cp -R "$(npm root -g)/agent-embassy/skills/embassy-peer" ~/.codex/skills/

Quickstart

Running in five minutes

Requirements first: macOS · Node ≥ 20 · the current agent-embassy release · Claude Code with peerProtocol 1 · the managed Codex App Server, all on the same machine and OS user. The ACP providers are optional and bring their own preconditions: DeepSeek needs a local dsh harness checkout and its own credentials, Grok Build needs its registry-pinned package to be resolvable by npx. A provider that isn't there renders degraded with its safe code — nothing refuses to boot over a missing or unexpected version. Single-user, same-machine only. The Claude side needs no Embassy commands (native ListAgents/SendMessage); only the conv_ token-holder can reply.

$ npm install -g agent-embassy
$ embassy serve
# inside your Codex task — ask the agent to run it:
$ embassy register-codex --alias codex-embassy@this-mac
# as the operator, pick a name from `embassy status` availablePeers:
$ embassy select-claude --alias claude-main@this-mac
# create the consent edge the next send uses:
$ embassy pair --from codex-embassy@this-mac --to claude-main@this-mac
# from the Codex task — body via stdin, never an argument:
$ embassy send --from codex-embassy@this-mac --to claude-main@this-mac --expects-reply <<'MSG'

Your agents can't talk to each other. Give them an embassy.

Embassy is a local, single-user gateway: your running Claude Code sessions and Codex desktop tasks exchange messages in both directions on one machine, under explicit operator steps. Every accepted send returns a delivery token and settles into one explicit terminal state.

Quickstart View on GitHub
Why

When two tools need to talk.

Your Claude session asks your Codex task a question mid-flow — you never switch windows or paste a thing.

Codex fires a question to Claude while you're away; the reply routes back and a receipt confirms delivery.

Claude messages a running Codex task with its native tools — no plugin to install, no config to write.

How it works

Five steps, and only the ones that matter.

No Embassy accounts, no daemons, no configuration files — five acts, each visible in your terminal.

1ServeRun embassy serve in a terminal you trust. It stays in the foreground, writes the static dashboard pages — gateway-dashboard.html and its gateway-dashboard.zh-CN.html twin — into its private state directory, and never daemonizes. A host-wide lease ensures one broker per account.
2RegisterThe Codex task registers itself from inside its own process — ask the Codex agent to run embassy register-codex --alias codex-reviewer@this-mac as a shell step in its current turn. Registration makes the task visible to compatible live Claude sessions running as your OS user; selecting one Claude session makes it both the Codex destination and the only accepted inbound sender. Other senders settle with SENDER_NOT_PAIRED; serve --inbound open is the explicit opt-out. Accepted turns still use the Codex task's existing native approval and sandbox policy. Retire it with unregister-codex.
3SelectFor the Codex→Claude direction, you explicitly select the destination — embassy select-claude --alias <a name from availablePeers>. Sending never silently selects a discovered session.
4SendBodies arrive via stdin, 16 KiB maximum, and live only in memory. Sending to a busy Codex task queues the message; an idle target gets one ordinary turn.
5WatchOptional. embassy dashboard --live opens an authenticated browser view of the same metadata — a separate foreground process on 127.0.0.1 with only three confirmed route-consent actions: select, unselect, and refresh discovery. gateway-dashboard.html in the state directory is the inert offline copy: no script, no network, and no self-refresh — re-run embassy refresh-dashboard and reload.
Protocol truth

The register doesn't flatter.

Embassy's receipts mean exactly what they say — and nothing more.

Delivered means the receiver accepted it, never that a model completed it. Toward Codex, that is the App Server accepting the turn; toward Claude, release into the session’s native queue — not read, not completed. A confirmed write without a native terminal receipt reports as unconfirmed; an uncertain write reports as ambiguous and is never retried automatically. The CLI's initial acceptance returns a conversation token and a delivery token; held and transport_written are progress, never success. A Claude-originated failure settles as native expired with a safe reason code. The default merged notice policy avoids a duplicate terminal diagnostic frame; verbose and quiet modes remain available.

Queues are honest. Sending to a busy Codex task queues rather than interrupts — Embassy never steers another agent's mid-turn context. Queued messages drain in order once the target is idle, and queue age is visible on the dashboard — never silent.

Restarts drop bodies, on purpose. Message text is never persisted — not in state, logs, events, or the dashboard. If the broker stops, queued text is gone and nothing replays.

Unknown versions fail closed. Claude Code 2.1.226, peer protocol 1 — still-running 2.1.224 and 2.1.225 sessions stay compatible through patch upgrades — and Codex App Server 0.147.0. Anything Embassy cannot validate is refused rather than guessed compatible: an unrecognized session is not discoverable, an unrecognized App Server shape leaves the route unwritable. Support for new versions ships as a release — see the changelog.

embassy serve opens no TCP or HTTP listener; the opt-in live companion does. embassy dashboard --live is a separate foreground process that binds 127.0.0.1 on an ephemeral port for an authenticated metadata stream. It has no CORS, provider, or generic control surface; its only mutations are confirmed select, unselect, and refresh-discovery actions, rate-limited to six per minute. Authentication scopes the browser, not the machine: any process running as your OS user — including root and browser extensions — can read what the browser can read. embassy serve itself opens no network listener and makes no provider API call — no telemetry, no cloud component. It speaks only over local Unix sockets: its own control socket in a mode-0700 state directory, plus the provider-owned Claude peer sockets and the already-running Codex App Server socket it attaches to. The agents themselves are still cloud-backed: a routed message becomes input to an ordinary model turn, so its text reaches Anthropic or OpenAI exactly as if you had typed it into that session. "Local" describes the broker and the route, not model inference.

It is a new input path. Neither agent gains a tool it did not already have, and Embassy grants, relaxes, and answers nothing. But two products that could not exchange text now can — treat every routed message as untrusted input that may steer its receiver.

Quickstart

Honest requirements first.

  • macOS only (localhost only) · Node.js ≥ 20
  • Claude Code 2.1.226, installed and signed in — with a session running, or availablePeers is empty
  • Codex desktop with its managed App Server 0.147.0 running
# install and start the broker (foreground, trusted terminal)
npm install -g agent-embassy
embassy serve

# in another terminal: list the candidate sessions Embassy has discovered
embassy status
  availablePeers: ["advisor@this-mac", "researcher@this-mac"]

# optional, in a third terminal: authenticated metadata + bounded route consent
embassy dashboard --live

# inside the Codex task — ask the Codex agent to run this as a shell step:
embassy register-codex --alias codex-reviewer@this-mac

# as the operator: select one name from availablePeers above (yours will differ)
embassy select-claude --alias advisor@this-mac

# from the Codex task: send (body via stdin, never arguments)
embassy send-to-claude --from codex-reviewer@this-mac --to advisor@this-mac --expects-reply <<'MSG'
Please review the current approach and note the main risk.
MSG

# continue the thread with the returned token, from either side
embassy reply --conversation conv_<token> --alias codex-reviewer@this-mac <<'MSG'
Please expand on the second call site.
MSG

# the other direction needs nothing at all: a live Claude session sees
# codex-reviewer in its native ListAgents and messages it directly.

The full quickstart — session-UUID addressing, delivery semantics, the dashboard — is in the README.

## Binding

**Why**: emb-99 charter. With consent gone (emb-104) the only thing
`reply` did that `send` could not — answer from an unselected,
unpaired session via the transient-target path — no longer exists.
One verb fewer on the surface; threading is preserved because the
envelope is built from the conversation token, not from which RPC
was used.

**Deliverable** (base = emb-104 head): `send --conversation <token>`
as an alternative to `--to`, resolving target alias/binding from the
conversation record and keeping `assertReplyCaller` (caller owns one
end; binding unchanged else `CONVERSATION_ROUTE_RETIRED`); `reply`
stays as a thin alias (same handler) for one release because the
`<embassy-reply-hint>` text is in flight in existing envelopes — the
hint text itself switches to the `send --conversation` form. Tests:
a reply via `send --conversation` threads (same conversationId in
the envelope) and is refused for a non-owner; `reply` alias
byte-equivalent. Docs/skill/CHANGELOG Unreleased (Changed).

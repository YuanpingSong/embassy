## Binding

**Why**: emb-99 charter, slice 5 — the one behavior change on the
send path. Founder ruling 2026-09-02, verbatim: "the consent edge -
signed". Standing trust-model directive: provenance marking + OS
boundary + anti-runaway are the whole safety model; consent edges
were "unnecessary permissioning". Today a first message needs
register-codex → select-claude → pair → send, and a message before
the edge fails `SENDER_NOT_PAIRED`/`not_found`. After this slice the
permission is: same UID, same host (or a configured federation
node), addressed by alias; the provenance envelope names the sender.

**Deliverable** (base = emb-103 head):
- DELETE consent: `pair`/`unpair`/`select-claude`/`unselect-claude`
  (CLI + control methods + service handlers + `resolvePairEndpoints`
  + `ConsentOwnerError`), `requireConsent` on `enqueueMessage`
  (store.ts ~2007 / ~1330), all consent helpers/validators/rekey/
  capacity/snapshot fields (`consentEdges`, `pair` on record types,
  `maxConsentEdges`/`EMBASSY_MAX_PAIRS`), `gatewayInboundModes` /
  `serve --inbound open` / `config.inboundMode` (store ~1384: native
  ingress no longer requires an edge), the `pairing` and `selection`
  activity kinds, the peer-wire consent fields (peer protocol is 2,
  v3-only — drop them), `store.enqueueNativeReply`'s
  `transientTarget/consentEdge:null` special case (it was a consent
  workaround; `reply` keeps working through the ordinary path).
- IMPLICIT ROUTES on send (service `sendToClaude`/`sendToCodex`):
  when the target Claude alias has no route, resolve it via
  `resolveClaudeSelector(alias, refresh=true)` and install the route
  exactly as `selectClaude` did — registration reuse on the same
  (hostId, routeHandle), displacement settlement of a re-anchored
  session's prior route, `assertWorkspaceDisjoint` — then enqueue.
  A sending Claude session likewise gets its own route installed on
  first send under its verified identity. Unknown alias →
  `CLAUDE_ROUTE_NOT_FOUND` (or the existing not_found code) with a
  one-line hint to run `embassy refresh`.
- COLLISION FENCE MOVES INTO SEND (emb-94 preserved, strengthened):
  refresh happens inside the send path; a colliding alias is a hard,
  non-retryable `PEER_ALIAS_COLLISION` naming the alias — never
  pick-first; collisions stay sticky under incomplete discovery
  (`collidingClaudeAliases` retention); `availablePeers` keeps
  filtering colliders so `status` never lists an unaddressable name.
- Recovery copy (store ~2998): "re-register, select, and pair
  routes" → "re-register Codex tasks". Persisted state loses
  `consentEdges` (shape change under schema 5; no further bump).
- Docs: README quickstart collapses to register-codex → send;
  "Registration and pairing" vocabulary bullet rewritten as
  "Registration and provenance"; SECURITY consent sections
  (~132–145) rewritten to the OS-boundary model; GATEWAY-ARCHITECTURE
  pairing threaded through many sections — rewrite honestly, delete
  §consent; SKILL.md §Pair providers deleted and the send teaching
  updated; site "consent is per edge" bullet rewritten; relocated
  public-docs assertions pinning pair/unpair wording deleted;
  forbidden terms: `select-claude`, `unselect-claude`, `embassy
  pair`, `unpair`, `SENDER_NOT_PAIRED`, `consent edge`, `--inbound`.
  CHANGELOG Unreleased: Removed + Changed lines.
- Tests: new — send to a discovered, never-selected Claude alias
  succeeds and installs the route; collision → PEER_ALIAS_COLLISION
  with no route installed; sticky collision under partial scan;
  re-anchored session reuses the registration and the prior route is
  settled `endpoint_retired`; workspace-disjoint refusal; Codex →
  unknown Claude alias → not-found with the refresh hint; `pair`/
  `select_claude` → UNKNOWN_METHOD; state with `consentEdges` key
  is refused as unknown-key (documented reset). Surgery across
  gateway-service (~55 pair hits), gateway-cli (~29), gateway-control
  (~33), gateway-store (~19), peer-transport (~3), provenance,
  skill-package.

**Acceptance**: check green; `--help` shows none of the four verbs
or `--inbound`; a live round trip is NOT required at this gate
(cutover drill covers it); grep zero for `consent|pair(` in src/
except justified; FULL GATE: PM check + adversarial read + taste
review (behavior change on the send path).

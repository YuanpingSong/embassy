## Binding

**Why**: founder, 2026-09-03, in session: "v3 has been successful in
achieving its stated goal but I think there is further room to make
our project even more efficient and focused." The founder updated
the swe3 seat to GPT-6 Astra (high reasoning) and asked for a
cleanup pass led by that seat. Same criteria as emb-99: daily value,
low maintenance, low operational friction.

**Founder broadening, 2026-09-03**: "the current pass is about current
quality — GPT-6 Astra has much better coding capability than GPT-5.6
Sol — use this new model to clean up any awkward code that we have. My
goal is actually a bit broader than just focus." So category (e)
below is first-class, not incidental.

**Deliverable (this ticket is AUDIT-FIRST; no edits)**: a read-only
audit of main at 8a5e7a1 against the shipped contract (README,
CHANGELOG 3.0.0, SECURITY, GATEWAY-ARCHITECTURE, the skill),
producing a candidate list the PM prices into deletion/correction
slices. Each candidate: what, file:lines, why it is dead/redundant/
drifted, deletion size, blast radius, and the regression evidence
that would prove the deletion safe. Categories: (a) dead code —
functions/exports/control params/safe codes never produced/hints
never rendered/config keys/test-only helpers shipped at runtime;
(b) redundant abstractions — e.g. the two Codex transports, the
Claude helper protocol layers, duplicated file readers, the store's
projection vs live shapes; (c) contract drift — any doc sentence not
true of the code; (d) the known backlog: destination-side handoff
refusal surfacing as `ambiguous` (should be a refusal code); no
token-free operator removal of stranded peer routes and no Claude-
route retirement; `snapshot.health` degraded-by-construction on an
idle broker; the envelope's reserve-time sourceAlias; `--help`
omitting --succeeds/--expects-reply/--from/--to/--conversation; the
m5dev pnpm+npm double install note. (e) CODE QUALITY — awkward or oversized functions, duplicated logic,
tangled control flow, unclear names, inconsistent error handling,
over-general helpers with one caller, comments that explain what the
code should have said: each candidate names the file:lines, the
better shape in a sentence, and the evidence that the refactor is
BEHAVIOR-PRESERVING (which tests already pin the behavior; which
wire/CLI outputs must stay byte-identical; what new test pins it if
none does). No new concepts (verbs, flags, codes, config, persisted
fields) ride a quality slice. Propose a slice order that keeps
`npm run check` green after each landing.

**Process**: same as v3 — each slice frozen with a handoff (base,
head, diff stat, concept accounting, platform-bound tests named),
PM check re-run + adversarial read, CI-green landing on main, records
per ticket. Quality refactors touching the send path, the store, or
the protocols get the FULL gate (adversarial + taste); elsewhere the
light gate. A refactor is priced like a deletion: value = code that
is easier to hold in the head, cost = risk × review time. No slice starts before the PM prices the candidate list.
The engineer's seat is swe3 (Codex CLI, GPT-6 Astra high); PM reviews
stay Opus/Fable.

## Binding

Evidence (PM-read): CI run 33989439531 attempt 1 (emb-129 lane, head 320422a): Ubuntu 22 failed test 286 "a peer waiter kicks cleanly deferred mail and exact receipt settles it once" (gateway-service.test.ts:1068, duration 232 ms); Ubuntu 20 failed test 287 "native Claude STEER text reaches a peer mailbox only through the ordinary lane" (:1100). Both expected peerReceipt `{accepted:true, code:"ok"}` and got `{accepted:false, code:"route_mismatch"}`. Attempt 2 (unchanged head) green. Test 288 "queued peer mail resumes once after restart…" (same family) was already in the backlog as intermittent. The emb-129 diff in that file is two deleted lines in an unrelated synthetic code set; the failing tests are untouched. Saved log: job tmp emb129-ci/attempt1-failed.log sha256 5b64760f22a3cd22d9046e3f4e5d69fe32d050c8c082e3054a163a7617273299.

Mechanism (PM-traced, to be confirmed by characterization): both fixtures build LocalPeerMailboxProvider with `receiptTimeoutMs: 100` and a frozen `now`. peer-mailbox.ts:96–97 arms a real setTimeout for min(receiptTimeoutMs, deadline−now) that deletes the receipt and resolves false; if the runner takes >100 ms between awaitPeer resolving and the peerReceipt call, the receipt is gone, the provider throws, and service.ts:255–271 maps the code to `route_mismatch` (the MISMATCH/CHANGED/ADDRESS/ROUTE_UNREGISTERED bucket).

Scope: (1) characterization first — a deterministic test that lets the receipt timer fire before the receipt call (fake timers or receiptTimeoutMs: 0) and asserts the exact code today; name the BridgeError code the mailbox throws for an expired/unknown receipt (file:line). (2) Fixture honesty — the three tests' 100 ms timeout is a runner-speed assumption; either fake the timer or raise it to a bound that cannot be crossed by a slow runner, without slowing the suite (state the new bound and why). (3) Code honesty — if an expired receipt really maps to `route_mismatch`, decide whether that is the truthful public code (it tells an operator the route changed when the receipt merely expired); if not, map it to the existing `not_found`/`expired`-class code and document it (control.ts:126/450 unions). No new concept; no new public code unless one of the existing ones is truthful.

Size 1 / E1 ≤50 changed lines (src ≤15, tests ≤35). Light gate. Proof: the characterization fails on the parent and passes after; the three tests survive 20 local iterations (`node --test --test-repeat` or a loop); CI READ at the exact head.

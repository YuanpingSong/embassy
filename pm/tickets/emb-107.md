## Binding

**Why**: emb-99 charter; founder ruling 2026-09-02: the dashboard was
overkill (never viewed) but "we still need some measure of human
observability — a terminal `embassy status` command (or variant)
that is human friendly." Today `status` prints the raw JSON snapshot
and `health` says `degraded` for reasons that do not matter.

**Deliverable** (base = emb-106 head):
- `embassy status`: human-readable when stdout is a TTY; JSON when
  piped or with `--json` (byte-identical to today's snapshot so
  scripts and the skill keep working). Human view, top to bottom:
  broker line (pid, version, uptime, state dir); connectors that
  matter only — claude, codex, and any registered shell peer — each
  as one line with a plain state word and, when degraded, the safe
  code AND the remedy sentence (reimplement the ~150 lines of
  attention/overall derivation the dashboard model had, WITHOUT any
  consent concept); routes table: alias · provider · idle/busy/stale
  · queue depth · last seen (relative); recent messages (last N,
  default 10, `--recent <n>`): time, from → to, state, latency,
  ~60-char single-line body preview (bodies are already in the
  snapshot; the README disclosure from emb-100 stands); actionable
  alerts only. `status` triggers `refresh_discovery` first so the
  list is fresh. Exit code stays 0 when the broker answers; the
  overall word is informational.
- `embassy watch`: terminal tail over `observe_snapshot` polling —
  prints new `snapshot.messages` rows by sequence (time, from → to,
  state transitions as they settle) and activity rows (route
  installed/retired, discovery, peer refresh) as a secondary line;
  `--json` streams the same as JSONL; Ctrl-C clean exit.
- `embassy check`: self-test round trip — discovers the first
  registered Codex task (or a named `--to`), sends a marked message
  that the recipient's skill is taught to answer with one line, waits
  for `delivered` and for the reply, and prints each hop with timing
  and the safe code on failure; bounded (default 60 s); exit non-zero
  on any hop failure. This is the upstream-drift tripwire: run it
  after any Claude Code / Codex CLI update. The `embassy-peer` skill
  gains the one-line "answer a check" rule.
- Orphaned Codex registration (emb-100 engineer finding #3): `status`
  marks a registration whose task is unobservable for > N minutes and
  names the operator remedy (`register-codex --succeeds` from the new
  task, or `unregister-codex` from the old one).
- Docs: README "See it" section with a captured status example;
  SKILL.md teaches `status --json`; CONFIGURATION rows for
  `EMBASSY_STATUS_RECENT` if any; CHANGELOG Unreleased (Added).
- Tests: renderer snapshot tests against fixture snapshots (healthy;
  codex degraded MANAGED_CODEX_UNAVAILABLE; alias collision; stale
  shell peer; busy route with queue); TTY vs piped selection;
  `--json` byte-equality with the raw snapshot; `watch` prints a new
  message once and settles; `check` happy path with fake adapters,
  and each hop failure with its code.

**Gate**: full (adversarial + taste) — adapter/provenance-adjacent
and the founder's stated observability requirement.

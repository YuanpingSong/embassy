## Binding

**Why**: found by swe3 during the emb-111 docs slice with a read-only
synthetic proof (/tmp/emb111-helper-bound-proof.mjs): claude-helper-
supervisor.ts ~124–137 checks the alias and `#helpers.size`, then
AWAITS the factory, then inserts — a second `advertise` for the same
alias entering during the await passes the check too. With
maxHelpers=1 and an async fake factory: factoryCalls 2, tracked 1,
the overwritten helper closed by NOBODY: close() (claude-helper-
supervisor.ts ~193–196) iterates only #helpers.values(), so the
displaced client is outside both the cap and shutdown cleanup
(repro: clientCloseCalls [0,1] only after an explicit close). providers.ts
~505–511 delegates directly and service.ts ~857–860 launches
reconciliation without joining it, so the overlap is reachable from
ordinary route churn. Same-UID blast radius: one leaked child +
socket + possibly a duplicate registry record until shutdown.

**Deliverable**: reserve on admission — record the pending alias
(and count it against the cap) BEFORE the factory await; release the
reservation on failure; AND make shutdown cleanup complete — either
close the displaced client at replacement time or track every
created client so close() reaches it; the repro's clientCloseCalls
must equal every created client. No new
concepts; the docs from emb-111 then get the "pending creations are
not reserved" clause removed. Characterization first: the repro as a
red test on the parent (two concurrent advertise calls, maxHelpers
1 → exactly one factory call, one tracked helper, one close), then
green. R3: light gate + adversarial read; helper/supervisor suite.

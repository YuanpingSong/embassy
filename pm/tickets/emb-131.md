## Binding

Evidence (PM, 2026-09-05, m5dev broker 3.0.0, route codex-embassy-swe3@m5dev busyPolicy queue): `embassy status --json` message rows for PM→swe3 sends show state "queued" for 40+ minutes across several of the engineer's turn boundaries (it sent ACKs and freezes in between), e.g. rows at 21:21:43 (197 B), 21:35:09 (515 B), 21:38:37 (2,642 B) still "queued" at 22:00 while a 21:56 send is "dispatching"; the route's `queueDepth` read 0 at the same time. The 2,642 B message (the U3 tail rulings) was demonstrably never received: the engineer's U3 freeze does not mention it and it asked afterwards for the very rulings it contained. Earlier in the day the same pattern appeared and the engineer coded emb-127 against a superseded instruction.

Scope: (1) characterize — a route in state busy with busyPolicy queue: does the deferred item get requeued when the route returns to idle (service requeue / wake loop), and does the public row state follow? Reproduce with the fake Codex provider: busy → send → idle → expect delivery + row `delivered`. (2) If the item is dropped or never rescheduled, fix the requeue path; if only the row state lags, fix the projection. (3) Whichever it is, `status` must not show queueDepth 0 while rows are "queued".

Size 1 / E1 ≤50 unless the characterization shows a design gap — contest before widening. FULL send-path gate (settlement). Proof: parent characterization red/green; CI READ.

Correction (same day, later reading): the route showed `queueDepth: 7` and the engineer then acknowledged a 40-minute-old message ("Delayed U1 ruling received; no reopening needed") — so queued items are NOT dropped; they drain FIFO, apparently one per idle window, and each drained item starts a fresh Codex turn during which newer sends queue again. With an engineer that works in long turns the backlog ages by tens of minutes and stale instructions arrive after they are superseded. Re-scoped: (1) confirm the one-per-idle-window drain and the earlier queueDepth-0-while-rows-queued inconsistency (stale projection?); (2) product fix direction to price: deliver ALL queued items for a conversation in ONE turn (batch drain) so a busy peer catches up in a single wake, and/or let a sender supersede its own earlier queued message in the same conversation; (3) `status` must show the queue depth truthfully. Size may become 2 — contest with the map.

title: Claude registry scan caps entries before sorting — visibility past 256 files depends on directory order
status: open
opened: 2026-09-28

- 2026-09-28 Found via emb-140 CI (Ubuntu red twice on test/claude-peer.test.ts:492). claude-peer.ts discover(): opendir entries are capped at the limit (256 display / 4096 prepared) and only then sorted, so with more registry files than the cap, which sessions are visible is decided by filesystem order, not by name or recency. Effect: on a machine with >256 registry files a live session can be undiscoverable to an unselected send (CLAUDE_PEER_TARGET_UNKNOWN) while ENTRY_LIMIT_EXCEEDED is counted. Not seen in the field (largest registry observed is far below 256). Price after 4.7.1: effort small, blast radius medium (discovery path, security-reviewed in 4.6.0). Options for the engineer: read names up to the hard ceiling then sort and slice; or prefer live/newest records. The emb-140 test change only stops the fixture depending on this; it does not fix it.

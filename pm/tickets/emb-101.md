  drop `dsh-`/`grok-`; `acp_prompt` kind out; `config.ts` hardwired
  ACP aliases out; `server.ts` ACP instantiation out; `claude-peer.ts`
  source-name pattern → `/^codex-/`; envelope recipient profiles for
  deepseek/grok out; `probe:*` scripts stay (Codex-only).

  (`split_brain`/`orphaned`/`attached`, `/Applications` matching).
  KEEP the managed-socket-holder check (`managed_layout_missing`) —
  it drives `MANAGED_CODEX_UNAVAILABLE` connector degradation

  (v2 precedent): a schema-4 file yields the existing

  updated (it will be re-touched by emb-104/106). This is the ONE
  bump for the v3 line; later slices change shape under 5 freely
  until release.
- Rider (emb-100 F6): the "federated named routes are read-only"
  property is currently emergent (decoder UUID requirement +
  `reg_` handle grammar) and undefended at the store —
  `removeOwnedRouteAtomic` matches alias + binding only. Add an
  explicit `federated_peer` mode refusal at the service
  (`unregisterCodex`) AND at the store removal path, and replace the
  misnamed test in gateway-service.test.ts (~807–825, which proves a
  handle mismatch, not the property) with one that presents a
